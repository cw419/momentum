测试质量审计报告

  Storage 专项审计发现三类严重反模式，且互相叠加。localStorageAdapter.test.ts 和 SupabaseStorage.test.ts
  两个主测试文件本质上都在测试"方法 A 是否调用了方法 B"，而非"系统行为是否正确"——这意味着代码里的绝大多数 bug
  无法被它们捕获。目前整个 storage 层唯一有实际价值的测试只有
  localStorageAdapter.integration.test.ts，但它的覆盖范围极为有限。11个子接口 / 约 61 个方法中，只有 ChainStore
  的部分方法有行为级测试，其余 10 个子接口行为覆盖均为零。

  ---
  一、同义反复测试（Tautological Tests）

  问题本质：Mock 返回 X，然后断言结果是 X，或者断言 mock 被调用——这类断言无论实现对错都永远为真。

  1.1 localStorageAdapter.test.ts 第 79–231 行 — "delegates all... methods"

  // 把 storage 工具模块整体 mock 掉
  vi.mock('../storage', () => ({ saveChains: vi.fn(), ... }));

  // 然后断言：调用了 mock
  expect(storageUtilsMock.saveChains).toHaveBeenCalledWith(chains);

  这等于测试"适配器内部调用了正确的工具函数"。如果适配器把参数顺序反转、把 Date 对象序列化丢失、或者把链ID
  混淆，测试依然绿灯。它测的是 wiring，不是行为。

  严重度：HIGH。这150 行测试提供的安全感是虚假的。

  1.2 SupabaseStorage.test.ts 第 420–459 行 — "proxies auth... calls to API modules"

  // mock 所有子 API 模块
  vi.mock('../chainsApi', () => ({ getChains: vi.fn().mockResolvedValue([]) }));
  // ...

  // 断言：调用了 mock
  expect(chainsApiMock.getChains).toHaveBeenCalled();

  整个 SupabaseStorage 类的测试实质是"转发表测试"：只验证 SupabaseStorage.getChains() 内部是否调用了
  chainsApi.getChains()，而不验证最终返回的 Chain[] 对象是否正确。

  严重度：HIGH。

  ---
  二、过度Mock / Mock 了被测系统（Over-mocking / Mock SUT）

  SupabaseStorage.test.ts 把以下 API 模块全部 mock 掉：

  - chainsApi、sessionsApi、historyApi
  - rsipApi、rsipIntentApi、taskTimeApi
  - authApi、userSettingsApi、bettingApi、checkinApi

  真正藏有 bug 的地方被完全跳过：

  ┌─────────────────────────────────────────┬──────────────────────────────────────────┐
  │             被mock 跳过的层             │             该层能出什么 bug             │
  ├─────────────────────────────────────────┼──────────────────────────────────────────┤
  │ chainMapper.ts / sessionMapper.ts       │ snake_case → camelCase 字段映射错误      │
  ├─────────────────────────────────────────┼──────────────────────────────────────────┤
  │ Zod schema 解析                         │ 数据库返回的字段类型不符导致运行时崩溃   │
  ├─────────────────────────────────────────┼──────────────────────────────────────────┤
  │ deletedAt 等可空字段的 null → Date 转换 │ 反序列化后 deletedAt 变成字符串而非 Date │
  └─────────────────────────────────────────┴──────────────────────────────────────────┘

  chains.test.ts 等 API 模块级测试确实覆盖了 mapper，但它们 mock 了Supabase 客户端，仍然无法测试"一个完整的 storage
  接口调用最终产出正确的业务对象"这条完整路径。

  严重度：HIGH。SupabaseStorage 的行为覆盖实际为零。

  ---
  三、缺乏故障揭示能力（Lack of Fault-revealing Capability）

  localStorageAdapter.integration.test.ts 是目前唯一有价值的测试，但有以下具体缺口：

  ┌────────────────────────────────────────────────────────┬───────────────────────────────────────────┐
  │                     缺失的测试场景                     │              会漏掉什么 bug               │
  ├────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 空状态：新localStorage 下getChains() 返回 []           │ 初始化时崩溃无法发现                      │
  ├────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ upsertChain 幂等性：同一 chain 执行两次，列表仍只有1条 │ 重复写入导致数据膨胀                      │
  ├────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ appendCompletionHistory append 语义：调用两次后有2条   │ 覆盖写成追加/追加写成覆盖互换，测试不报错 │
  ├────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ 软删除 →恢复 round-trip                                │ 恢复逻辑的字段赋值错误无法捕获            │
  ├────────────────────────────────────────────────────────┼───────────────────────────────────────────┤
  │ cleanupExpiredDeletedChains 的日期阈值边界             │ 硬编码历史日期若换机器时区可能失效        │
  └────────────────────────────────────────────────────────┴───────────────────────────────────────────┘

  SessionStore（6 方法）、HistoryStore（3 方法）、RsipStore（16 方法）、TaskTimeStatsStore（5
  方法）均无任何行为级测试。这30 个方法的实现可以全部写错，测试套件依然全绿。

  ---
  四、Storage 契约测试改进方案

  核心问题诊断

  当前测试层级错位：

  现在：  SupabaseStorage → [mock] chainsApi → [跳过] mapper → Chain[]
  理想：  SupabaseStorage → chainsApi → mapper → [mock] supabase client → Chain[]

  只需要把 mock 边界下移一层（mock Supabase 客户端，而不是 API 模块），就能让整条业务路径真实执行。

  改进架构：Adapter Contract Pattern

  新建 src/storage/__tests__/MomentumStorage.contract.test.ts，用同一套spec 函数驱动两个实现：

  // src/storage/__tests__/MomentumStorage.contract.test.ts
  import { describe, it, expect, beforeEach, vi } from 'vitest';
  import type { MomentumStorage } from '../ports';
  import { localStorageAdapter } from '../localStorageAdapter';
  import { SupabaseStorage } from '../../infra/storage/supabase/SupabaseStorage';
  import { createUnitChain } from '../../test/factories';

  //── Supabase 客户端 mock：在API 模块层以下，让 mapper 真实执行 ──────────────
  vi.mock('../../lib/supabase', () => {
    const db: Record<string, Record<string, unknown>[]> = {};

    const queryBuilder = (table: string) => {
      const rows = () => (db[table] ??= []);
      return {
        select: vi.fn().mockReturnThis(),
        upsert: vi.fn().mockImplementation((data: unknown) => {
          const arr = Array.isArray(data) ? data : [data];
          arr.forEach((row: Record<string, unknown>) => {
            const idx = rows().findIndex(r => r['id'] === row['id']);
            if (idx >= 0) rows()[idx] = row;
            else rows().push(row);
          });
          return Promise.resolve({ data: arr, error: null });
        }),
        // ...根据实际 API 模块的调用链补全eq / order / then
      };
    };

    return {
      supabase: {
        from: vi.fn().mockImplementation((table: string) => queryBuilder(table)),
        auth: { onAuthStateChange: vi.fn(() => ({ data: { subscription: { unsubscribe: vi.fn() } } })) },},
    };
  });

  // ── 共享契约 spec：同一套断言，两个实现都必须通过 ─────────────────────────────
  function runChainStoreContract(getStorage: () => MomentumStorage) {
    describe('ChainStore contract', () => {
      let storage: MomentumStorage;
      beforeEach(() => { storage = getStorage(); });

      it('空状态下 getChains 返回空数组', async () => {
        expect(await storage.getChains()).toEqual([]);
      });

      it('saveChains + getChains 保留所有字段，包括 Date 类型', async () => {
        const chain = createUnitChain({ id: 'c-1', createdAt: new Date('2026-01-01T00:00:00.000Z') });
        await storage.saveChains([chain]);
        const [loaded] = await storage.getChains();
        expect(loaded.id).toBe('c-1');
        expect(loaded.createdAt).toBeInstanceOf(Date);           // 验证反序列化
        expect(loaded.createdAt.toISOString()).toBe('2026-01-01T00:00:00.000Z');
      });

      it('upsertChain：新增 +幂等更新', async () => {
        const chain = createUnitChain({ id: 'c-1', name: 'original' });
        await storage.upsertChain(chain);
        await storage.upsertChain({ ...chain, name: 'updated' });
        const all = await storage.getChains();
        expect(all).toHaveLength(1);          // 不能变成两条
        expect(all[0].name).toBe('updated');
      });

      it('软删除排除在getActiveChains 之外', async () => {
        await storage.saveChains([
          createUnitChain({ id: 'keep' }),
          createUnitChain({ id: 'delete' }),
        ]);
        await storage.softDeleteChain('delete');
        expect((await storage.getActiveChains()).map(c => c.id)).toEqual(['keep']);
      });

      it('软删除 → 恢复 round-trip', async () => {
        await storage.saveChains([createUnitChain({ id: 'c-1' })]);
        await storage.softDeleteChain('c-1');
        expect(await storage.getActiveChains()).toHaveLength(0);
        await storage.restoreChain('c-1');
        expect(await storage.getActiveChains()).toHaveLength(1);
      });
    });
  }

  function runHistoryStoreContract(getStorage: () => MomentumStorage) {
    describe('HistoryStore contract', () => {
      let storage: MomentumStorage;
      beforeEach(() => { storage = getStorage(); });

      it('appendCompletionHistory 是追加语义，不是覆盖', async () => {
        await storage.appendCompletionHistory({ chainId: 'c-1', completedAt: new Date('2026-01-01') } as never);
        await storage.appendCompletionHistory({ chainId: 'c-1', completedAt: new Date('2026-01-02') } as never);
        expect(await storage.getCompletionHistory()).toHaveLength(2);
      });
    });
  }

  // ── 在两个实现上跑同一套契约 ──────────────────────────────────────────────────
  describe('MomentumStorage contract — localStorageAdapter', () => {
    beforeEach(() => localStorage.clear());
    runChainStoreContract(() => localStorageAdapter);
    runHistoryStoreContract(() => localStorageAdapter);
    // runSessionStoreContract(() => localStorageAdapter);// runRsipStoreContract(() => localStorageAdapter);  //
  后续补充
  });

  describe('MomentumStorage contract — SupabaseStorage', () => {
    runChainStoreContract(() => new SupabaseStorage());
    runHistoryStoreContract(() => new SupabaseStorage());
  });
